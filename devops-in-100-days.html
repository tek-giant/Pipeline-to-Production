DevOps learning roadmap

DevOps in 100 Days: from basics to advanced

This journey is designed to turn daily practice into real DevOps confidence. Each day gives you a focus area, a practical task, a useful note, and an idea you can turn into portfolio evidence.

Start day 1 Back to articles

This roadmap covers the major DevOps toolchain. No roadmap can cover every tool ever created, but this one covers the skills and tools employers most often expect: Linux, Git, Bash, Python, networking, AWS, Docker, Jenkins, GitHub Actions, Terraform, Ansible, Kubernetes, Helm, Argo CD, Flux, security scanning, monitoring, logging, databases, and SRE practices.

Daily practice

100 daily tips, tasks, notes, and ideas

Day 1

Understand DevOps

Task: Write what DevOps means in your own words. Note: DevOps is culture, automation, measurement, and sharing. Idea: Publish a short LinkedIn learning post.

Day 2

Set up your workstation

Task: Install VS Code, Git, a terminal, and a package manager. Note: Your local setup should be repeatable. Idea: Document your setup steps.

Day 3

Linux file system

Task: Practise ls, cd, pwd, mkdir, cp, mv, rm, cat, less. Note: Linux fluency is a DevOps foundation. Idea: Create a command cheat sheet.

Day 4

Linux permissions

Task: Practise chmod, chown, groups, sudo. Note: Permission errors are common in deployments. Idea: Explain 755 and 644 in a note.

Day 5

Processes and services

Task: Use ps, top, kill, systemctl, journalctl. Note: Services fail loudly in logs first. Idea: Troubleshoot a stopped service.

Day 6

Networking basics

Task: Learn IP, DNS, ports, TCP, HTTP, TLS. Note: Many production issues are networking issues. Idea: Diagram browser to server traffic.

Day 7

Network tools

Task: Practise ping, curl, nslookup, dig, netstat or ss. Note: curl is a daily DevOps tool. Idea: Test a public API endpoint.

Day 8

SSH

Task: Create SSH keys and connect to a Linux host. Note: Keys are safer than passwords. Idea: Write a guide on secure SSH basics.

Day 9

Logs

Task: Search logs with grep, tail, journalctl. Note: Logs tell the story of failure. Idea: Build a log investigation checklist.

Day 10

Linux mini project

Task: Deploy a simple web server on Linux. Note: Basics become real when a service runs. Idea: Add screenshots to GitHub.

Day 11

Git basics

Task: Practise init, add, commit, status, log. Note: Git is the memory of delivery. Idea: Create your first DevOps notes repository.

Day 12

Branching

Task: Create branches and merge them. Note: Branching supports safe collaboration. Idea: Draw a feature branch workflow.

Day 13

Pull requests

Task: Open a pull request on GitHub. Note: Reviews are quality gates. Idea: Add a PR checklist to a repository.

Day 14

GitHub essentials

Task: Learn README, issues, releases, tags. Note: Good repositories are easy to understand. Idea: Improve one README file.

Day 15

Bash scripting

Task: Write a backup or health-check script. Note: Shell scripts automate routine tasks. Idea: Publish a useful admin script.

Day 16

Bash variables and loops

Task: Use variables, conditions, and loops. Note: Scripts need predictable input handling. Idea: Build a script that checks disk usage.

Day 17

Python for DevOps

Task: Read a JSON file and print useful values. Note: Python is strong for APIs and automation. Idea: Parse a cloud inventory file.

Day 18

APIs

Task: Call an API with curl and Python requests. Note: DevOps tools are often API-driven. Idea: Build a small status checker.

Day 19

YAML and JSON

Task: Read and edit YAML and JSON configs. Note: Pipelines and Kubernetes depend on structured files. Idea: Create a YAML examples folder.

Day 20

Automation mini project

Task: Build a script that checks service health and writes a report. Note: Automation should remove toil. Idea: Add usage instructions.

Day 21

Cloud basics

Task: Learn regions, availability zones, IAM, VPC. Note: Cloud design starts with foundations. Idea: Draw a basic AWS architecture.

Day 22

AWS IAM

Task: Study users, groups, roles, policies. Note: Least privilege matters. Idea: Create an IAM policy explanation post.

Day 23

AWS EC2

Task: Launch an EC2 instance and connect by SSH. Note: EC2 teaches compute basics. Idea: Deploy Nginx manually first.

Day 24

AWS S3

Task: Create a bucket and upload files. Note: Object storage supports artifacts, logs, and backups. Idea: Host a static page.

Day 25

VPC networking

Task: Learn subnets, route tables, internet gateways, NAT. Note: VPC design affects security and reachability. Idea: Build a VPC diagram.

Day 26

Load balancing

Task: Understand ALB, listeners, target groups, health checks. Note: Healthy targets receive traffic. Idea: Explain target group health checks.

Day 27

Elastic Beanstalk

Task: Study how Beanstalk deploys an app. Note: Managed platforms still need DevOps understanding. Idea: Document a WAR deployment flow.

Day 28

CloudWatch

Task: Explore metrics, logs, alarms, dashboards. Note: Monitoring starts before incidents. Idea: Create a basic alarm plan.

Day 29

Cloud cost control

Task: Learn budgets, tags, rightsizing, cleanup. Note: Cost is an engineering signal. Idea: Write a cleanup checklist.

Day 30

Cloud mini project

Task: Deploy a small app to AWS with monitoring. Note: Tie compute, networking, logs, and cost together. Idea: Publish architecture notes.

Day 31

Docker basics

Task: Run containers with docker run, ps, logs, exec. Note: Containers package runtime dependencies. Idea: Containerise a simple app.

Day 32

Dockerfile

Task: Write a Dockerfile. Note: Small images build faster and reduce risk. Idea: Compare image sizes.

Day 33

Docker images

Task: Build, tag, inspect, and push an image. Note: Tags connect code to deployments. Idea: Use commit SHA as an image tag.

Day 34

Docker volumes

Task: Mount data into a container. Note: Containers are disposable; data is not. Idea: Run a database with a volume.

Day 35

Docker networks

Task: Connect two containers on a network. Note: Services need predictable communication. Idea: Link app and database containers.

Day 36

Docker Compose

Task: Build a compose file for app and database. Note: Compose is useful for local stacks. Idea: Add a README with start commands.

Day 37

Container registries

Task: Push to Docker Hub, GHCR, or ECR. Note: Registries are artifact stores. Idea: Document image naming rules.

Day 38

Image scanning

Task: Scan an image with Trivy. Note: Vulnerability scans belong in pipelines. Idea: Fix one vulnerable base image.

Day 39

Container logs

Task: Read logs and pass environment variables. Note: Apps should log to stdout and stderr. Idea: Add structured logs to a demo.

Day 40

Container mini project

Task: Build, scan, and push an app image. Note: This becomes the base for CI/CD. Idea: Add a diagram to GitHub.

Day 41

CI/CD concepts

Task: Learn CI, CD, artifacts, gates, environments. Note: Pipelines create repeatable delivery. Idea: Sketch a pipeline flow.

Day 42

GitHub Actions

Task: Create a workflow that runs tests. Note: CI should start on pull requests. Idea: Add a status badge.

Day 43

Actions build workflow

Task: Build and upload an artifact. Note: Artifacts prove what the pipeline created. Idea: Save test reports.

Day 44

Jenkins basics

Task: Understand jobs, agents, plugins, credentials. Note: Jenkins is flexible but needs care. Idea: Compare Jenkins and Actions.

Day 45

Jenkinsfile

Task: Write a declarative Jenkinsfile. Note: Pipeline as code is reviewable. Idea: Add build, test, and archive stages.

Day 46

Pipeline credentials

Task: Use secrets safely in CI. Note: Secrets should not be printed in logs. Idea: Write secret-handling rules.

Day 47

Quality gates

Task: Add linting and code quality checks. Note: Fast feedback improves developer flow. Idea: Add SonarQube or lint checks.

Day 48

Deployment stages

Task: Add staging and production stages. Note: Environments separate risk. Idea: Add manual approval before production.

Day 49

Pipeline notifications

Task: Notify success or failure. Note: Notifications should be useful, not noisy. Idea: Send a Slack or email summary.

Day 50

CI/CD mini project

Task: Build a full test, image, scan, deploy pipeline. Note: This is core portfolio material. Idea: Record a short demo.

Day 51

Terraform basics

Task: Learn providers, resources, variables, outputs. Note: IaC makes infrastructure repeatable. Idea: Create an EC2 module.

Day 52

Terraform state

Task: Learn local and remote state. Note: State must be protected. Idea: Document S3 and DynamoDB locking.

Day 53

Terraform modules

Task: Build a reusable VPC or S3 module. Note: Modules standardise good patterns. Idea: Add examples and variables.

Day 54

Terraform plan in CI

Task: Run terraform fmt, validate, plan in CI. Note: Review plans before apply. Idea: Add plan output to pull requests.

Day 55

OpenTofu and IaC choices

Task: Compare Terraform, OpenTofu, CloudFormation, Bicep, Pulumi. Note: Tool choice follows team context. Idea: Write a comparison table.

Day 56

Ansible basics

Task: Write an inventory and playbook. Note: Ansible is useful for configuration and orchestration. Idea: Install Nginx with Ansible.

Day 57

Ansible roles

Task: Split a playbook into a role. Note: Roles make automation reusable. Idea: Create a webserver role.

Day 58

Packer

Task: Learn immutable image building. Note: Golden images reduce configuration drift. Idea: Build an AMI concept plan.

Day 59

Vault and secrets

Task: Learn secret storage and rotation concepts. Note: Secrets need lifecycle management. Idea: Design a secrets flow.

Day 60

IaC mini project

Task: Provision infrastructure and configure it automatically. Note: Terraform plus Ansible is a strong combo. Idea: Publish architecture and code.

Day 61

Kubernetes basics

Task: Learn clusters, nodes, pods, control plane. Note: Kubernetes schedules containers. Idea: Create a glossary.

Day 62

kubectl

Task: Practise get, describe, logs, exec, apply. Note: kubectl is your daily cluster interface. Idea: Make a kubectl cheat sheet.

Day 63

Deployments

Task: Deploy an app with replicas. Note: Deployments manage rollout and rollback. Idea: Demonstrate a rollback.

Day 64

Services

Task: Expose pods with ClusterIP and NodePort. Note: Services give stable networking. Idea: Explain service discovery.

Day 65

Ingress

Task: Route HTTP traffic to an app. Note: Ingress handles external access. Idea: Add TLS notes.

Day 66

ConfigMaps and Secrets

Task: Inject config into pods. Note: Separate configuration from images. Idea: Compare env vars and mounted files.

Day 67

Probes

Task: Add readiness and liveness probes. Note: Health checks protect traffic. Idea: Break a probe and observe behaviour.

Day 68

Requests and limits

Task: Set CPU and memory requests and limits. Note: Scheduling needs resource signals. Idea: Explain OOMKilled.

Day 69

Namespaces and RBAC

Task: Create namespaces, roles, role bindings. Note: Access control matters in clusters. Idea: Build a least-privilege example.

Day 70

Storage

Task: Learn PV, PVC, StorageClass. Note: Stateful workloads need careful design. Idea: Deploy a database for learning.

Day 71

Helm

Task: Install and customise a Helm chart. Note: Helm packages Kubernetes apps. Idea: Create your own simple chart.

Day 72

Kustomize

Task: Create dev and prod overlays. Note: Overlays manage environment differences. Idea: Compare Helm and Kustomize.

Day 73

Autoscaling

Task: Learn HPA and cluster autoscaling. Note: Scaling follows metrics. Idea: Load test a demo app.

Day 74

Kubernetes troubleshooting

Task: Debug ImagePullBackOff and CrashLoopBackOff. Note: Events are your friend. Idea: Build a troubleshooting guide.

Day 75

Kubernetes mini project

Task: Deploy an app with ingress, probes, config, and Helm. Note: Production readiness is layered. Idea: Add diagrams and rollout notes.

Day 76

GitOps basics

Task: Learn desired state and pull-based deployment. Note: Git becomes the source of truth. Idea: Draw a GitOps flow.

Day 77

Argo CD

Task: Study applications, sync, health, drift. Note: Argo CD makes deployment state visible. Idea: Sync a sample app.

Day 78

Flux

Task: Compare Flux with Argo CD. Note: Both support GitOps patterns. Idea: Write a comparison note.

Day 79

Secret management in GitOps

Task: Learn Sealed Secrets, External Secrets, SOPS. Note: Plain secrets should not live in Git. Idea: Design a secure secret workflow.

Day 80

DevSecOps basics

Task: Map security checks into CI/CD. Note: Security should be early and actionable. Idea: Add a security stage to a pipeline.

Day 81

SAST and dependency scanning

Task: Try CodeQL, Snyk, Dependabot, or OWASP Dependency-Check. Note: Prioritise exploitable risk. Idea: Fix one dependency alert.

Day 82

Container and IaC scanning

Task: Try Trivy, Checkov, tfsec, or Terrascan. Note: Scan code before deployment. Idea: Publish scan results in CI.

Day 83

Policy as code

Task: Learn OPA, Gatekeeper, or Kyverno. Note: Policies create repeatable guardrails. Idea: Block privileged pods.

Day 84

Supply chain security

Task: Learn SBOMs, signing, provenance, SLSA. Note: Trust the build path. Idea: Generate an SBOM for an image.

Day 85

GitOps security mini project

Task: Deploy an app through GitOps with scans and policy checks. Note: Secure delivery should still be usable. Idea: Create a portfolio case study.

Day 86

Monitoring basics

Task: Learn metrics, logs, traces, dashboards, alerts. Note: Observability explains behaviour. Idea: Define key signals for an app.

Day 87

Prometheus

Task: Learn scraping, metrics, PromQL, alerts. Note: Metrics should answer operational questions. Idea: Create a simple PromQL note.

Day 88

Grafana

Task: Build a dashboard. Note: Dashboards should show service health clearly. Idea: Create a golden signals dashboard.

Day 89

Logging stack

Task: Learn Loki, ELK, or OpenSearch. Note: Logs help explain incidents. Idea: Centralise app logs.

Day 90

Tracing

Task: Learn OpenTelemetry and distributed traces. Note: Traces show request journeys. Idea: Trace a slow request path.

Day 91

SRE basics

Task: Learn SLIs, SLOs, SLAs, error budgets. Note: Reliability needs targets. Idea: Define one SLO for a demo API.

Day 92

Incident response

Task: Write a runbook. Note: Incidents need calm, repeatable steps. Idea: Create an alert-to-runbook example.

Day 93

Post-incident reviews

Task: Write a blameless review template. Note: Learning matters more than blame. Idea: Simulate an incident and review it.

Day 94

Database operations

Task: Learn migrations, backups, restore testing, replication. Note: Data changes require extra care. Idea: Add Flyway or Liquibase to a demo.

Day 95

Observability mini project

Task: Monitor a deployed app with metrics, logs, alerts, and a runbook. Note: Visibility completes delivery. Idea: Publish a dashboard screenshot.

Day 96

Portfolio project 1

Task: Build a CI/CD pipeline for a containerised app. Note: Show the path from commit to deployment. Idea: Include a pipeline diagram.

Day 97

Portfolio project 2

Task: Provision cloud infrastructure with Terraform. Note: Make your README clear and professional. Idea: Include cost and security notes.

Day 98

Portfolio project 3

Task: Deploy a Kubernetes app with Helm and GitOps. Note: Show rollout, rollback, and health checks. Idea: Add Argo CD screenshots.

Day 99

Interview preparation

Task: Practise explaining your projects. Note: Employers want reasoning, not memorised commands. Idea: Write STAR stories for incidents and automation.

Day 100

Publish and improve

Task: Publish your projects, blog notes, and learning summary. Note: DevOps learning continues through practice. Idea: Share your 100-day journey on LinkedIn.
