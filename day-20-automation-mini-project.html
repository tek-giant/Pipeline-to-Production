Project goal

Build automation that answers a real operations question.

The project question is simple: are the important services healthy right now? A good DevOps script should answer that question consistently, without requiring someone to remember every command manually.

Why this matters

Automation should reduce toil.

Toil is repeated manual work that does not create lasting value. Health checks, smoke tests, log scans, config validation, and report generation are good candidates for automation.

Configuration

Put service targets in JSON

The script should not hardcode every endpoint. A configuration file makes the automation easier to update when services, URLs, environments, or owners change.

Python script

Check each endpoint and write a report

This script reads the JSON file, checks each service, writes a report, prints a summary, and exits with `1` when one or more services fail. That final exit code is what makes the script useful in CI/CD. 

#!/usr/bin/env python3
import json
from datetime import datetime, timezone
from pathlib import Path

import requests

CONFIG_FILE = Path("config/services.json")
REPORT_FILE = Path("reports/latest-report.txt")


def check_service(service):
    name = service["name"]
    url = service["url"]
    expected = service.get("expected_status", 200)

    try:
        response = requests.get(url, timeout=5)
        actual = response.status_code
        healthy = actual == expected
        detail = f"expected {expected}, got {actual}"
    except requests.exceptions.RequestException as error:
        healthy = False
        detail = str(error)

    return {
        "name": name,
        "url": url,
        "owner": service.get("owner", "unknown"),
        "healthy": healthy,
        "detail": detail,
    }


def main():
    config = json.loads(CONFIG_FILE.read_text())
    REPORT_FILE.parent.mkdir(parents=True, exist_ok=True)

    results = [check_service(service) for service in config["services"]]
    failures = [result for result in results if not result["healthy"]]

    lines = [
        f"Environment: {config['environment']}",
        f"Checked at: {datetime.now(timezone.utc).isoformat()}",
        "",
    ]

    for result in results:
        status = "PASS" if result["healthy"] else "FAIL"
        lines.append(f"{status} | {result['name']} | {result['owner']} | {result['detail']}")

    REPORT_FILE.write_text("\n".join(lines) + "\n")
    print("\n".join(lines))

    return 1 if failures else 0


if __name__ == "__main__":
    raise SystemExit(main())

CI/CD usage

Use the script as a deployment gate

The same script can run after deployment. If the service check passes, the pipeline continues. If it fails, the pipeline stops and stores the report as evidence. 

name: service-health-check

on:
  workflow_dispatch:
  push:
    branches:
      - main

jobs:
  health-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install dependencies
        run: pip install requests

      - name: Run health check
        run: python scripts/health_check.py

      - name: Upload report
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: health-check-report
          path: reports/latest-report.txt

Config validity

Run JSON, YAML, Docker Compose, Ansible, Terraform, or Kubernetes validation commands.

Version check

Confirm the running version matches the version that was deployed.

Operational thinking

Good automation exposes the right information quickly.

Clear input

Use config files so service targets are easy to review and change.

Useful output

Write reports that explain what passed, what failed, and why it matters.

Safe failure

Return non-zero exit codes when checks fail so pipelines can stop safely.

Timeouts

Use timeouts for endpoint checks so one slow service does not hang the whole script.

No secrets

Do not print tokens, passwords, or private headers in logs or reports.

Documentation

Explain how to run the script locally and how it behaves in CI/CD.

Troubleshooting

What to check when the automation fails

Bad config path

The script cannot find `config/services.json` from the current working directory.

Invalid JSON

The config file has a missing comma, quote, bracket, or incorrect nesting.

Network failure

The endpoint may be blocked by DNS, firewall, proxy, routing, or TLS issues.

Wrong status code

The service may return 301, 401, 403, 500, or 503 instead of the expected 200.

Missing package

The environment may not have the `requests` package installed.

Weak report

The report may need more context, such as owner, environment, URL, and timestamp.
