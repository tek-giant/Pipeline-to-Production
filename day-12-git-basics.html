Git basics: the memory of DevOps delivery

Git is where DevOps work becomes traceable. Pipelines, Terraform modules, Dockerfiles, Kubernetes manifests, Helm charts, scripts, runbooks, and application code all need version control so teams can review changes, understand history, and recover safely.

Mental model

What Git is really doing

Git tracks snapshots of your files. Every commit records what changed, who made the change, when it happened, and the message explaining why. In DevOps, that history is critical because infrastructure and delivery systems must be auditable and reversible.

work Working tree

Edit files such as `main.tf`, `Jenkinsfile`, `deployment.yaml`, or `README.md`.

stage Staging area

Select the exact changes that belong together before committing.

commit Local history

Create a snapshot that can be reviewed, compared, tagged, or rolled back.

push Remote repository

Share the change with GitHub, GitLab, Azure Repos, or Bitbucket.

Why Git matters

DevOps starts with version control

CI/CD tools normally pull from Git. Terraform changes are reviewed in Git. Kubernetes manifests are stored in Git. GitOps depends on Git as the desired state. Without Git discipline, delivery becomes difficult to prove, repeat, and recover.

What to practise

Learn the everyday commands first

Master `status`, `add`, `commit`, `log`, `diff`, `branch`, `switch`, `remote`, `push`, and `pull`. These are the commands you will use constantly before moving into pull requests, CI/CD, and GitOps workflows.

Hands-on lab

Create a DevOps notes repository

This lab creates a small local repository for DevOps notes. It is intentionally simple, because the goal is to understand Git's workflow before adding branches, pull requests, and automation. 

# 1. Create a project folder
mkdir devops-notes
cd devops-notes

# 2. Initialise Git
git init

# 3. Create your first note
echo "# DevOps Notes" > README.md
echo "Day 12: Git basics" >> README.md

# 4. Check what Git can see
git status

# 5. Stage and commit the file
git add README.md
git commit -m "Add first DevOps notes"

Command breakdown

The Git commands every DevOps engineer should know

git init

Creates a new Git repository in the current folder.

git status

Shows changed, staged, untracked, and committed files.

git add

Moves selected changes into the staging area.

git commit

Saves a snapshot with a useful message.

git log

Shows commit history and helps trace decisions.

git diff

Shows exactly what changed before staging or committing.

git branch

Lists or creates branches for separate streams of work.

git switch

Moves between branches safely and clearly.

Real DevOps use

Git is not only for application code

Infrastructure as Code

Terraform, CloudFormation, Bicep, and environment variables need reviewable history.

CI/CD pipelines

Jenkinsfiles, GitHub Actions, GitLab CI, and Azure DevOps YAML should be versioned.

Kubernetes

Manifests, Helm charts, Kustomize overlays, and policies belong in Git.

Automation

Bash, Python, Ansible, PowerShell, and maintenance scripts need traceability.

Documentation

Runbooks, deployment notes, incident procedures, and READMEs improve team operations.

GitOps

Tools like Argo CD and Flux treat Git as the source of truth for deployment state.

Compare changes

Use `git diff` before you commit

`git diff` helps you avoid committing accidental changes. This is especially important when editing infrastructure, deployment manifests, pipeline files, or production runbooks. 

# Show unstaged changes
git diff

# Stage a file
git add README.md

# Show staged changes before commit
git diff --staged

# Commit only when the change is clear
git commit -m "Document Git basics workflow"

Remote repository

Connect local work to GitHub

A local commit is useful, but a remote repository makes the work visible to other people and available to CI/CD systems. Replace the URL below with your own GitHub repository. 

# Add a remote repository
git remote add origin https://github.com/tek-giant/devops-notes.git

# Rename the current branch to main
git branch -M main

# Push local commits to GitHub
git push -u origin main

Good habits

Commit like a DevOps engineer

Small commits

Keep commits focused so reviews and rollbacks are easier.

Clear messages

Explain the purpose, not only the file that changed.

Review diffs

Check `git diff` and `git diff --staged` before committing.

No secrets

Never commit passwords, tokens, private keys, or `.env` files.

Use branches

Separate feature work, fixes, experiments, and production changes.

Document decisions

Use README notes and commit messages to explain why a change exists.

Troubleshooting

Common beginner Git problems

Wrong folder

Run `pwd`, `ls`, and `git status` to confirm you are inside the right repository.

Nothing to commit

There may be no changes, or the files may already be committed.

Untracked files

Use `git add filename` when you want Git to track a new file.

Remote rejected

Pull first, check branch names, or confirm you have permission to push.

Accidental secret

Remove it quickly, rotate the secret, and learn proper secret handling.

Merge conflict

Open the file, choose the correct content, test it, then commit the resolution.
