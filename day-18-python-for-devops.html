Python for DevOps: automate the work around the tools

Bash is excellent for fast Linux tasks. Python becomes powerful when DevOps work needs structure: reading JSON, calling APIs, validating configuration, producing reports, handling errors, and building reusable automation that other engineers can understand.

Mental model

Python is the glue for structured DevOps automation.

DevOps engineers rarely use Python just to prove they know Python. They use it to solve operational problems: collect data, make decisions, call APIs, format output, reduce manual checks, and make automation safer to repeat.

Why Python

It handles structured work better than shell scripts.

Python is useful when the task involves dictionaries, lists, API responses, error handling, files, conditionals, retry logic, or reports. It makes complex automation easier to read and test.

Where it fits

It sits beside Bash, not against it.

Use Bash for quick command-line tasks. Use Python when the logic grows, data becomes structured, or the script needs to be reused by other people and pipelines.

Hands-on lab

Build a cloud inventory report from JSON

A realistic DevOps task is taking machine-readable infrastructure data and turning it into a useful report. This small script reads a JSON inventory and prints the key information a team might need during support, audit, migration, or incident response. 

{
  "servers": [
    {
      "name": "payments-api-01",
      "environment": "production",
      "private_ip": "10.0.4.21",
      "owner": "platform-team",
      "status": "running",
      "region": "eu-west-2",
      "tags": ["api", "payments", "critical"]
    },
    {
      "name": "reporting-worker-01",
      "environment": "staging",
      "private_ip": "10.0.8.13",
      "owner": "data-team",
      "status": "stopped",
      "region": "eu-west-2",
      "tags": ["worker", "reports"]
    }
  ]
}
#!/usr/bin/env python3
import json
from pathlib import Path

inventory_path = Path("inventory.json")
inventory = json.loads(inventory_path.read_text())

for server in inventory["servers"]:
    name = server["name"]
    environment = server["environment"]
    private_ip = server["private_ip"]
    owner = server["owner"]
    status = server["status"]
    region = server["region"]
    tags = ", ".join(server["tags"])

    print(f"{name} | {environment} | {private_ip} | {owner} | {status} | {region} | {tags}")

API automation

Call a service health endpoint with Python

Many DevOps platforms expose APIs: GitHub, GitLab, Jenkins, Kubernetes, AWS, Azure, monitoring tools, and incident platforms. Python helps you call those APIs, handle failures, and produce useful output. 

#!/usr/bin/env python3
import requests

url = "https://example.com/health"

try:
    response = requests.get(url, timeout=5)
    response.raise_for_status()
except requests.exceptions.Timeout:
    print(f"TIMEOUT: {url} did not respond quickly enough")
except requests.exceptions.HTTPError as error:
    print(f"HTTP ERROR: {url} returned {error.response.status_code}")
except requests.exceptions.RequestException as error:
    print(f"REQUEST FAILED: {error}")
else:
    print(f"OK: {url} is healthy")

CLI scripts

Make scripts flexible with arguments

A script becomes more useful when the user can pass an environment, file path, service name, or threshold without editing the code. This is how small scripts start becoming professional tools. 

#!/usr/bin/env python3
import argparse

parser = argparse.ArgumentParser(description="Check a DevOps environment name.")
parser.add_argument("--environment", required=True, choices=["dev", "staging", "production"])
args = parser.parse_args()

print(f"Running validation for {args.environment}")
python check_environment.py --environment dev python check_environment.py --environment staging python check_environment.py --environment production

Safer habits

Write Python like an operations engineer.

Timeouts

Always set timeouts when calling APIs so scripts do not hang forever.

Errors

Catch likely failures and print useful messages that explain the problem.

Inputs

Validate arguments and file paths before doing important work.

Secrets

Read sensitive values from environment variables or secret stores, not hardcoded strings.

Exit codes

Return success or failure clearly so CI/CD tools can react correctly.

Logs

Use readable output for small scripts and structured logging for larger automation.

Troubleshooting

Common Python automation problems

Missing package

The script uses a library such as requests but the environment has not installed it.

Bad JSON

The input file is not valid JSON, or the script expects a key that is not present.

No timeout

An API call hangs and blocks the pipeline or support script.

Hardcoded values

The script works only in one environment because values are fixed in the code.

Weak errors

The script fails but does not explain what went wrong or what was being checked.

No exit status

CI/CD shows success even though the script found a real problem.
