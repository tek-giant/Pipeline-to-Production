Understanding the Linux file system like a DevOps engineer

Linux is where many DevOps tasks become real: servers, containers, CI/CD runners, Kubernetes nodes, automation scripts, logs, service files, and configuration directories. The faster a person can navigate Linux, the faster they can troubleshoot production-style problems.

Mindset

The file system is a map of the machine

DevOps engineers use Linux paths to understand where applications live, where configuration is stored, where logs are written, and where temporary or generated files may affect performance. Knowing the map reduces guesswork during troubleshooting.

Outcome

Move from guessing to knowing where to look

When a service fails, a strong first response is not panic. It is knowing which directory to inspect, which command to run, which log to read, and which file might explain the behaviour.

Core directories

The Linux paths every DevOps beginner should know

These directories appear again and again in cloud servers, Docker containers, CI/CD workers, and Kubernetes nodes. Learn what they usually contain, then practise moving through them from the terminal.

/home User files and workspaces

Common place for user projects, scripts, SSH configuration, and personal working directories.

/etc System configuration

Often contains service settings, package configuration, environment files, and system defaults.

/var Logs and changing data

Important for `/var/log`, application logs, caches, queues, and files that change while systems run.

/tmp Temporary files

Used by applications and processes for short-lived files. It can matter when disk space runs low.

/usr Installed programs and libraries

Contains many user commands, shared files, libraries, and application resources.

/opt Optional third-party software

A common location for manually installed tools, agents, scanners, and vendor packages.

/root Root user's home directory

Separate from `/home`; useful to recognise when working with administrator-level access.

/bin Essential commands

Contains core binaries needed for basic system operations and command-line work.

Command guide

The commands to practise today

pwd

Show the current working directory.

ls

List files and folders in the current directory.

ls -la

List everything, including hidden files, with details.

cd

Move between directories.

mkdir

Create a new directory.

touch

Create an empty file or update a timestamp.

cat

Print a file's content to the terminal.

cp

Copy files or directories.

mv

Move or rename files and folders.

rm

Remove files carefully. Check the path before running it.

less

Read long files page by page.

tree

View a directory structure as a tree when installed.

Real DevOps use

Where this knowledge appears in actual work

Troubleshooting

Find logs quickly

When an application fails, logs often explain the failure. Linux practice helps readers know to inspect places such as `/var/log`, service logs, container logs, and application-specific log directories.

Configuration

Understand service settings

Many services depend on configuration stored under `/etc` or application folders. DevOps engineers need to read settings without accidentally damaging production systems.

Automation

Write better scripts

Scripts become safer when paths are clear, directories are checked before use, and commands are run from predictable locations.

Safe habits

Navigation mistakes to avoid

Do not run remove commands until the current path is confirmed with `pwd`.

Do not edit system configuration files without making a backup or understanding the service impact.

Do not assume every Linux system has the same tools installed by default.

Do not store credentials in plain text notes inside a project folder.

Do not ignore hidden files; many important settings begin with a dot.

Do not confuse the root directory `/` with the root user's home directory `/root`.
