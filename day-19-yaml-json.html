YAML and JSON: the configuration language of DevOps

DevOps engineers work with configuration every day. YAML and JSON appear in Kubernetes, CI/CD pipelines, Ansible, Terraform outputs, AWS CLI responses, monitoring payloads, policies, and automation scripts. Learning their structure makes troubleshooting faster and deployments safer.

Mental model

Configuration is code that tells tools what to do.

A deployment can fail because of one wrong space, a missing quote, an incorrect key, or a list placed at the wrong level. YAML and JSON look simple, but they control serious systems. Treat them with the same care as application code.

yamlHuman-friendly

Used heavily for Kubernetes, Ansible, GitHub Actions, Helm, and Docker Compose.

jsonMachine-friendly

Used heavily for APIs, AWS CLI output, Terraform output, policies, and integrations.

riskSmall syntax errors

Indentation, commas, quotes, and nesting can break deployments.

habitValidate first

Lint locally and in CI before applying changes to real environments.

YAML

Designed for people to read and write.

YAML uses indentation to show structure. It is clean and readable, but that also means spacing matters. One misplaced indentation level can change what a tool understands.

JSON

Designed for systems to exchange data.

JSON is strict: keys and strings use double quotes, objects use braces, arrays use brackets, and commas separate values. It is common in APIs and automation output.

Hands-on lab

Represent the same deployment in YAML and JSON

Both formats can describe the same information. The difference is syntax. Practise reading the structure first: environment, replicas, image name, image tag, ports, and labels. 

environment: production
replicas: 3
image:
  name: payments-api
  tag: v1.0.0
ports:
  - 8080
  - 8443
labels:
  app: payments
  owner: platform-team
{
  "environment": "production",
  "replicas": 3,
  "image": {
    "name": "payments-api",
    "tag": "v1.0.0"
  },
  "ports": [8080, 8443],
  "labels": {
    "app": "payments",
    "owner": "platform-team"
  }
}

Kubernetes example

YAML controls what runs in the cluster

This manifest describes a Deployment. Notice how indentation shows relationships: `containers` belongs under the Pod template, `ports` belongs under the container, and `containerPort` belongs under the port item. 

apiVersion: apps/v1
kind: Deployment
metadata:
  name: payments-api
spec:
  replicas: 3
  selector:
    matchLabels:
      app: payments-api
  template:
    metadata:
      labels:
        app: payments-api
    spec:
      containers:
        - name: payments-api
          image: ghcr.io/example/payments-api:v1.0.0
          ports:
            - containerPort: 8080

GitHub Actions example

YAML controls when automation runs

CI/CD workflows are also configuration. The structure tells GitHub which branch events should start the workflow, which runner to use, and which steps should execute. 

name: build-and-test

on:
  pull_request:
    branches:
      - main

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout source
        uses: actions/checkout@v4

      - name: Run tests
        run: npm test

Validation

Check configuration before it reaches production

Validation is a habit, not a luxury. A good DevOps workflow checks syntax locally, checks structure in pull requests, and uses dry-run commands before applying important changes.

python -m json.tool config.json yamllint deployment.yaml kubectl apply --dry-run=client -f deployment.yaml docker compose config ansible-playbook playbook.yml --syntax-check terraform output -json

Common mistakes

The small errors that cause big failures

Wrong indentation

YAML changes meaning when an item is placed at the wrong level.

Tabs in YAML

Use spaces. Tabs can cause parsing failures or confusing behaviour.

Missing commas

JSON requires commas between fields and array items.

Bad quotes

JSON strings require double quotes. YAML values may need quotes when values are ambiguous.

Wrong data type

A value may look right but be treated as a string, number, boolean, or list incorrectly.

Unknown key

A tool may reject a key, ignore it, or apply a default you did not expect.

Good habits

Configuration habits that make teams safer

Keep examples

Store working examples for Kubernetes, workflows, Ansible, and Docker Compose.

Use comments carefully

YAML supports comments, but JSON does not. Avoid relying on comments for critical logic.

Review diffs

Small indentation changes can be hard to notice without careful pull request review.

Validate in CI

Run linting and dry-run checks before merge so errors are caught early.

Separate environments

Use clear files or overlays for dev, staging, and production configuration.

Protect secrets

Do not commit secret values into YAML or JSON. Use secret stores and protected variables.
