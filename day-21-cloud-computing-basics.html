Cloud computing basics: the platform behind modern DevOps

Day 21 starts the cloud phase of the journey. Before running Terraform, Docker, Kubernetes, CI/CD, or observability platforms, a DevOps engineer needs to understand the cloud building blocks that support real production systems.

Big idea

Cloud is not only servers on the internet.

Cloud computing gives teams on-demand infrastructure and managed services. Instead of buying and managing every physical server, teams can provision compute, storage, networking, databases, monitoring, and security controls from a cloud provider such as AWS, Azure, or Google Cloud.

For DevOps, the important point is not just that resources are available quickly. The real value is that infrastructure can be automated, repeated, measured, secured, scaled, and improved using code and operational practices.

Why this matters

Most DevOps tools depend on cloud foundations.

Terraform provisions cloud resources. CI/CD deploys into cloud environments. Kubernetes often runs on managed cloud clusters. Monitoring tools collect signals from cloud workloads. Weak cloud basics make all of those areas harder to understand.

What this proves

You can think in systems, not isolated services.

A production application is a connected system: users, DNS, load balancers, networks, compute, storage, identity, monitoring, security, cost, backups, and recovery all matter together.

Core concepts

The cloud terms to understand first

These are the foundations that appear again and again in DevOps interviews, architecture diagrams, migration projects, troubleshooting sessions, and infrastructure-as-code work.

RegionGeographic location

Choose regions based on latency, compliance, resilience, and cost.

Availability ZoneIndependent data centre zone

Use multiple zones so one data centre issue does not take down the whole application.

ComputeWhere code runs

Virtual machines, containers, serverless functions, and managed platforms host applications.

StorageWhere data lives

Object storage, block storage, file systems, and databases support different data patterns.

NetworkHow systems communicate

VPCs, subnets, route tables, firewalls, NAT, private endpoints, and load balancers control traffic.

IAMWho can do what

Identity and access management controls permissions for users, services, pipelines, and workloads.

Service map

How cloud services support a real application

Do not memorise services as separate names. Learn the role each service plays in the system. That is how cloud knowledge becomes useful in production.

TrafficDNS + load balancer

Users need a reliable entry point and traffic must reach healthy targets.

ApplicationVMs, containers, serverless

The workload needs a secure and repeatable runtime.

ConfigurationSecrets + environment settings

Applications need controlled access to credentials and runtime values.

DataDatabase + object storage

Stateful data needs backups, encryption, access control, and recovery planning.

OperationsMetrics + logs + alarms

Teams need visibility before, during, and after incidents.

GovernanceTags + policies + cost controls

Cloud usage must be traceable, secure, and financially controlled.

DevOps angle

What a DevOps engineer should ask about every cloud design

A strong DevOps mindset looks beyond whether the resource exists. It asks whether the resource is secure, observable, repeatable, scalable, cost-aware, and recoverable.

SecurityWho has access?

Use least privilege, managed identities or roles, MFA, encryption, and audited access.

ReliabilityWhat happens if one zone fails?

Spread critical workloads across availability zones and plan failover paths.

AutomationCan this be rebuilt?

Use infrastructure as code, version control, reviews, and repeatable pipelines.

ObservabilityHow will we know it is healthy?

Collect logs, metrics, traces, alerts, dashboards, and runbooks.

CostIs this the right size?

Tag resources, clean unused assets, set budgets, and choose cost-aware designs.

RecoveryCan we restore quickly?

Test backups, document recovery steps, and understand RTO and RPO targets.

Day 21 takeaway

Cloud skill is about understanding how services work together.

A DevOps engineer does not need to know every cloud service on day one. The stronger skill is understanding the core building blocks, how traffic flows, how access is controlled, how systems are monitored, and how designs can be automated and recovered.
