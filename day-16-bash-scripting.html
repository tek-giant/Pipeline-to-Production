Bash scripting: turn repeated Linux work into automation

Bash scripting is where Linux commands become repeatable DevOps tools. A useful script can check services, validate disk usage, inspect logs, prepare deployments, support CI/CD steps, and reduce the number of manual checks engineers have to remember under pressure.

Automation model

What Bash scripting gives a DevOps engineer

A script should not just hide commands. It should make a task clearer, safer, faster, and easier to repeat. When a script is well written, another engineer can read it, understand it, run it, and improve it.

inputvalues

Service names, paths, thresholds, environments, or arguments.

logicchecks

Conditions decide what happens when something is healthy or broken.

actioncommands

Run Linux commands, API checks, file operations, or deployment helpers.

outputresult

Print useful messages and return the right exit code.

Why Bash matters

It sits close to real operations

Bash is often used directly on Linux servers, in Docker images, inside CI/CD pipelines, and during troubleshooting. Even when teams use Python, Ansible, or Terraform, Bash still appears in operational glue.

DevOps value

It reduces repeated manual checks

Scripts can standardise health checks, backup steps, log checks, deployment validation, and environment checks so different engineers get the same result from the same process.

Hands-on lab

Create a service health-check script

This script checks whether a service is active. It is a simple example, but the pattern is very useful for Nginx, Docker, SSH, Jenkins agents, monitoring agents, and application services. 

#!/usr/bin/env bash
set -euo pipefail

SERVICE_NAME="${1:-nginx}"

echo "Checking service: ${SERVICE_NAME}"

if systemctl is-active --quiet "${SERVICE_NAME}"; then
  echo "OK: ${SERVICE_NAME} is running"
  exit 0
else
  echo "ERROR: ${SERVICE_NAME} is not running"
  systemctl status "${SERVICE_NAME}" --no-pager || true
  exit 1
fi

Make it executable

Run the script properly

Save the script as `check-service.sh`, make it executable, and pass the service name as an argument. 

chmod +x check-service.sh

# Check Nginx
./check-service.sh nginx

# Check Docker
./check-service.sh docker

# Check SSH
./check-service.sh ssh

Script anatomy

Parts of a useful Bash script

Shebang

`#!/usr/bin/env bash` tells the system which interpreter to use.

Safety options

`set -euo pipefail` helps catch errors and unset variables early.

Variables

Store values like service names, paths, thresholds, and environments.

Conditions

Use `if` statements to decide what should happen next.

Messages

Print clear output so humans and pipelines understand the result.

Exit codes

Return `0` for success and non-zero for failure.

Disk check example

Build a script that warns about high disk usage

Disk checks are a classic Linux operations task. This script reads disk usage and exits with failure if the usage is above the threshold. 

#!/usr/bin/env bash
set -euo pipefail

THRESHOLD="${1:-80}"
USAGE=$(df / | awk 'NR==2 {gsub("%","",$5); print $5}')

echo "Disk usage: ${USAGE}%"
echo "Threshold: ${THRESHOLD}%"

if [ "${USAGE}" -ge "${THRESHOLD}" ]; then
  echo "ERROR: Disk usage is above threshold"
  exit 1
fi

echo "OK: Disk usage is within threshold"
exit 0

CI/CD usage

Use Bash scripts inside pipelines

CI/CD systems understand exit codes. If a Bash script exits with `1`, the pipeline can stop before a risky deployment continues. 

name: Validate server checks

on:
  pull_request:

jobs:
  smoke-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run smoke check
        run: |
          chmod +x scripts/check-disk.sh
          ./scripts/check-disk.sh 90

Safety

Good Bash habits

Quote variables

Use `"${VAR}"` to avoid issues with spaces and unexpected values.

Fail clearly

Use exit codes and useful error messages.

Check inputs

Validate arguments before running destructive commands.

Avoid secrets

Do not echo tokens, passwords, keys, or private values into logs.

Test safely

Run against dev environments before production.

Document usage

Add comments and README examples for other engineers.

Troubleshooting

Common Bash scripting problems

Permission denied

Run `chmod +x script.sh` or execute with `bash script.sh`.

Wrong shell

Use a clear shebang and avoid Bash-only features in `sh` scripts.

Unset variable

`set -u` helps catch missing values early.

Silent failure

Check exit codes and print useful messages.

Bad paths

Use absolute paths or validate working directory assumptions.

Dangerous deletes

Validate variables before using commands like `rm` or cleanup scripts.
