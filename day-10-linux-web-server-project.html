Project goal

Build something small but real

The goal is to deploy a simple Nginx website on Linux and verify it properly. This project connects file permissions, services, networking, SSH, logs, and troubleshooting into one practical workflow.

Hands-on lab

Deploy Nginx on Ubuntu or Debian

These commands use Ubuntu or Debian package management. On Amazon Linux, CentOS, or RHEL, the package manager and service names may be slightly different, but the DevOps thinking is the same. 

# 1. Update package information
sudo apt update

# 2. Install Nginx
sudo apt install nginx -y

# 3. Start the service now
sudo systemctl start nginx

# 4. Enable it after reboot
sudo systemctl enable nginx

# 5. Check the service status
systemctl status nginx --no-pager

Verification

Prove the web server is working

systemctl status nginx

Confirms whether the service is active or failed.

ss -tulnp | grep :80

Shows whether something is listening on HTTP port 80.

curl -I localhost

Checks headers and HTTP status from the local server.

curl http://SERVER_IP

Tests the page from another machine or your browser.

sudo journalctl -u nginx

Reads systemd logs for the Nginx service.

sudo tail -f /var/log/nginx/error.log

Follows Nginx error logs in real time.

Troubleshooting map

If the page does not load, check in this order

Service

Is Nginx active? Use `systemctl status nginx` and `journalctl -u nginx`.

Port

Is port 80 listening? Use `ss -tulnp | grep :80`.

Firewall

Is HTTP allowed? Check `ufw status`, security groups, or cloud firewall rules.

Content

Is the file in the correct path? Check `/var/www/html/index.html`.

Logs

Do the access or error logs explain the problem?

Network

Can you reach the server IP from your machine? Test with `curl` or browser access.

Firewall example

Open HTTP traffic safely

If the service works locally but not from your browser, the issue may be a firewall or cloud security rule. On Ubuntu with UFW, you can allow HTTP like this: 

sudo ufw status
sudo ufw allow 'Nginx HTTP'
sudo ufw status numbered

In AWS, Azure, or another cloud provider, you would also check the instance security group, network security group, route table, public IP, and load balancer rules.
